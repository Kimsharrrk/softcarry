## 📈 2. 포트폴리오 기재용 스토리 및 정량적 근거

### [문제 정의 (Bottleneck)]
- 원라이너(`curl / irm`) 특성상 수천 대의 PC가 일시에 스크립트를 요청할 경우, 매번 템플릿을 파싱/치환하는 CPU 연산 부하로 인해 요청이 지연되고 터미널 타임아웃 발생 위험이 있었습니다.

### [해결 방안 (Engineering Solution)]
1. **L1 In-Memory LRU + L2 Redis 기반 2계층 캐싱 구조 도입**:
   - 동일 OS 및 프리셋 조합의 스크립트를 메모리 상에 사전 캐싱하여 RTT 및 I/O를 제로화.
2. **비동기 O(1) 텔레메트리 큐잉**:
   - 기기별 설치 결과를 DB에 직접 동기식으로 쓰지 않고 메모리 버퍼 큐에 즉시 삽입(`202 Accepted`) 후 1초 배치 워커로 분산 처리.

### [실측 결과 (Impact)]
- **초당 처리량**: 최대 **52,024 req/s** 무장애 달성.
- **P99 지연 시간**: **5 ms** 수준으로 초고속 응답 보장.
